Architecture

Four layers, deliberately decoupled.

Adopt any one layer alone. Only the routing core is required — and it ships zero third-party dependencies.

Layer 1 · required

Routing Core

Two-signal task classifier, promotion gate with out-of-sample confirmation and FDR correction, and a route table that falls back to your static defaults on any uncertainty. Pure stdlib.

apex_router
Layer 2 · optional

Measuring Proxy

Fronts your provider, forwards every request byte-identically, and measures composition + usage for an offline policy tuner. A strict superset of a plain passthrough.

apex-router[proxy]
Layer 3 · optional

Offload Subsystem

Run work on a local model off the interactive path and measure whether it saved frontier tokens. Codegen counts only if the tests pass. Review is default-off — measured net-negative.

apex_router.ornith
Layer 4 · optional

Toolkit — codeqa

Grounded code Q&A: ripgrep retrieval + local model answering with file:line citations, plus a freshness gate that checks a doc's claims against live code.

apex_router.codeqa
The measuring proxy

Byte-identical forward.
Measured, not modified.

Every request passes through untouched and reaches your provider verbatim. The proxy only tees usage and composition into local telemetry — for an offline policy tuner.

  • Nothing leaves your machine — no phone-home, ever
  • Emits token counts, byte-class sizes, timing — never prompt text
  • Works with Anthropic + OpenAI wire formats out of the box
  • apex-router serve · apex-router proxy doctor

The offload subsystem

Local work, gated by your tests.

Codegen runs on the local model with thinking OFF, then runs the caller's tests. The saving is booked only when the code passes — otherwise it escalates to the frontier.

  • frontier_completion_tokens_saved counts only when gated + ok + not escalated
  • A wrong local answer the frontier must redo costs more than not offloading
  • Single-GPU serialized worker, one job at a time, one telemetry row each
  • Review lane is default-off — measured net-negative
Design decisions

The non-obvious calls, and why.

01

Static default is the floor, always

A data-starved cell defers to your hand-authored default. Worst case, you get exactly your static routing — no regression is possible on install.

02

Promotions need statistical evidence

Out-of-sample confirmation + FDR correction + replication across capture windows. A model that only looks better on its own sample does not get promoted.

03

The savings metric refuses to flatter itself

frontier_completion_tokens_saved counts a local call only when it was gated, passed, and not escalated. A raw completion contributes zero.

04

Codegen is gated by tests, or it doesn't count

A wrong local answer the frontier must redo costs more than not offloading. The codegen lane runs the tests and escalates on failure.

05

No agentic grading of untrusted code

codeqa's frontier judge is opt-in and HTTP-only — never routed through the agentic Claude/Codex CLIs that could execute scanned source.

06

Pure-stdlib core runs anywhere

The routing decision has zero third-party deps, so it runs on a box with only the Claude, Codex, and Kimi CLIs — no model server required.

◇

Honesty is load-bearing.

The proxy is measure-only. On a local, free model, the honest answer to "how much did apex save?" is exactly what the telemetry shows — not an inferred dollar figure. The standing rule: savings are token-equivalent, not dollars. Measurement, not attribution.

Install

One command. Arch-aware. Idempotent.

The installer is composable — adopt only what you need. The routing core ships immediately; the proxy, local tiers, and watchers are all opt-in.

bash — installing apex-router
--proxymeasuring proxy + offline tuner
--watchdrain + daily report watchers
--ornith-servelocal queue worker daemon
--ornith-tier largepull the 35B-A3B MoE tier
--no-ornithskip local model pulls
--verify-onlycheck install, change nothing
