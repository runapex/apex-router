## ONE baseline: Helicone alert notification

Helicone puts a readable breach summary before diagnostic fields and provides a direct investigation action [H3].
Its cost guidance uses graduated thresholds and time to react, which match datapce's budget problem [H2].
Use its summary-and-action structure, not its automatic routing or long metric names.

### Alerting guidance

Google SRE separates urgent pages from slower ticket alerts and recommends paired short and long windows [S1].
Datadog connects burn rate with time until depletion and uses both windows for an alert [D1].
These sources discuss reliability error budgets, not dollar budgets or context capacity.
Do not copy their numeric thresholds into datapce without separate validation.
Langfuse distinguishes missing data from OK and documents notifications on state transitions [F1].
Helicone recommends minimum request counts to reduce low-traffic false alerts [H1].

## Six proposed bands

Each example uses ASCII only.
Each length includes spaces and separators, but excludes a separate Hide control.
Reserve five additional columns for ` Hide`; every example still fits 80 columns.

| Scenario | Proposed band | Columns |
|---|---|---:|
| fresh | `apex GREEN | 5h 3% | context 10% | $0.12` | 40 |
| calm-fanout | `apex GREEN | 5h 22% | context 34% | $1.80 | tasks 3` | 51 |
| advice-differs | `apex AMBER 5h 62% | context 61% | $4.12/10 | tasks 7 | advice 2 | match 86%` | 75 |
| red-limit | `apex RED: Wait | 5h 95% | context 61% | $4.12 | tasks 3` | 55 |
| context-full | `apex GREEN | context 88%: Run /apex handoff | 5h 40% | $6.40 | tasks 1` | 70 |
| budget-burn | `apex AMBER: Pause new tasks | $9.10/10 | context 45% | left ~18m | 5h 50%` | 73 |

`GREEN`, `AMBER`, and `RED` retain the existing pressure-state meaning.
`GREEN` does not mean that context or spending is safe.
The context band therefore states the context action beside its measurement.
`tasks` counts all recorded dispatches, not running tasks.
`advice 2` counts tasks whose actual tier differs from advice.
`match 86%` describes backend requested-versus-actual tier matching, not advice agreement or answer quality.
The pane must explain both measures separately.

1. Keep the current model unchanged.
2. Show action text only when an urgent condition requires action.
3. Put the urgent action near the start, or beside its context measurement.
4. Show dollar spend against the configured budget.
5. Show depletion time as an estimate.
6. Move local completions, escalations, and detailed advice reasons into `/apex`.
7. Use color only as a second signal beside explicit text.

The fixture supplies the 18-minute estimate for budget-burn.
The RED fixture supplies a reset timestamp but no current clock for a reliable countdown.
Use `Wait` in that example instead of inventing a wait duration.
`/apex handoff` adds a template; the user must complete it and start a fresh session.
The command does not start a session or change the model.

## Pane changes

Put a one-line summary before all sections.
Use a summary row before the details in each section.

Example first line:

```text
AMBER: Pause new tasks; budget may run out in about 18 minutes.
```

| Order | Plain title | Summary and detail content |
|---:|---|---|
| 1 | Next step | State the primary action and cause. Show secondary risks below it. |
| 2 | Usage and limits | Show window usage, reset time, context, spend/budget, estimated depletion time. |
| 3 | Recent tasks | Summarize running/completed/failed counts. Show newest tasks first. |
| 4 | Local tasks: last 24 hours | Summarize completed, failed, escalated counts. Show queue time when known. |
| 5 | Model results | Show task type, model tier, sample count, completion rate, failure kinds, average tokens and time. |
| 6 | Advice and model matching | Separate advice agreement from requested-tier matching. Show reasons and sample limits. |
| 7 | Session details | Show task mix, skills, repositories, backend availability, and added-context size. |

The new Usage and limits section needs measured session data and budget configuration.
`paneSections` currently receives neither `Measure` nor `budgetUsd`.
This proposal requires those inputs; the current pane cannot derive them from dispatches.

### Example pane rows

Every example row fits 72 columns.

```text
AMBER: Pause new tasks; budget may run out in about 18 minutes.
Next step
  Pause new tasks to reduce spending.
  Models stay unchanged; you control each model choice.
Usage and limits
  Spent $9.10 of $10.00; $0.90 remains.
  Budget may run out in about 18 minutes at the current rate.
  5-hour limit used: 50%; context used: 45%.
Recent tasks
  2 tasks recorded; counts include finished tasks.
  Find pressure gate state file
    Type: explore; ran: opus; completed in 41 seconds.
    Total tokens: 41,000; no model advice for this task.
Model results
  explore / sonnet: 11 of 12 completed; 1 unavailable.
    Average total tokens: 38,000; average time: 52 seconds.
  Completion rate does not measure answer quality.
Advice and model matching
  2 tasks ran with a different tier from advice.
  Requested tier matched actual tier in 86% of judged records.
```

1. Split long task descriptions into continuation rows at word boundaries.
2. Keep each rendered row at 72 columns or fewer.
3. Keep costs, actions, outcomes, and model names visible.
4. Use horizontal space for related facts, not complete task histories.
5. Replace `tok(all)` with `Total tokens`.
6. Replace `μ` with `Average`.
7. Replace `▲` with `Different from advice` in task details.
8. Show unavailable values as `Unknown`, not zero or healthy.
9. Keep backend history separate from current-session totals.
10. Show recovery state and its remaining observation count in details, not the band.

## Top five rules, ranked

| Rank | Rule | Reason |
|---:|---|---|
| 1 | State the cause and next action for every urgent condition. | RED, high context, and budget depletion currently lack usable hints. |
| 2 | Keep the band advise-only. | Users retain model control; Helicone routing is outside this baseline. |
| 3 | Protect the action and key facts within the width limit. | The band must fit 80 columns, including controls; pane rows must fit 72. |
| 4 | Use plain labels and explicit units. | Symbols and abbreviations hide meaning; completion does not prove answer quality. |
| 5 | Separate pressure, context, spending, and missing data. | A GREEN pressure state must not hide another urgent condition. |
