## Baseline pick: VS Code status bar (with the k9s hint idea)
It puts the key state on the left and context on the right, and it reserves error color for blocking states only.
Each item is short text + one icon, so there is no jargon. That fits one line of 80 columns.
Add one k9s-style hint (`→ action`) only when the state needs action.

## Proposed bands (all ≤ 80 columns, measured below)
Rules used: state word not just color; plain words; `→ hint` only at WATCH/STOP or ctx ≥ 80%; hint is advice only (band never switches model).

## Pane changes (/apex)
1. Line 1 is a one-line summary: `STOP: 5h limit 95%. Pause or run /apex.` (same state word as band).
2. Section order: Now (state, hint) > Limits (5h, ctx, budget) > Advice (tasks that fit a cheaper model) > Helpers > Details.
3. Plain titles: "Limits" not "tok(all)"; "Helpers" not "routes"; "Confidence" not "conf"; "Local" not "↑".
4. Row width ≤ 72: label (12) + value; wrap or cut with "…" at 72. Put the key number first in each row.
5. Show a hint row only when the state is WATCH/STOP. Keep Details last and collapsed.
6. Never show a command that changes the model by itself; write "Try: ..." as advice.

## Top 5 rules, ranked
1. Every WATCH/STOP state and ctx ≥ 80% gets one `→ hint` (k9s hint idea). Fixes action_acc.
2. Use words for state (OK/WATCH/STOP), not color or glyph alone (VS Code: error color only for blocking).
3. Put state and urgent items on the left, context on the right (VS Code primary/secondary).
4. Show a module only when it matters (Starship `cmd_duration` shows only after 2 s). Drop ctx bar or helpers when room is short.
5. Stay ≤ 80 columns and use no jargon (▲ ↑ conf routes tok μ). Hints are advice; the band never changes the model.
