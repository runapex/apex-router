# Owner gold by cross-validation (2026-10-08): 222 labels, 15 corrections, judge 0.92 held out

The gold set was 182 single-pass model labels (`by=model:claude-opus-5-5`) and 0 owner
labels. The owner delegated the labelling with one condition: a label counts as the owner's only
when it is cross-validated and reconciled. This note is the record of that procedure, so the
`by=user` rows in `gold.jsonl` can be read for what they are.

## Procedure

1. **Export.** Every gold row in force with a task (182) via `labels export-review --ids`, plus
   40 new tasks via `--strata suspected-fail:25,random:15` (seed 7). The existing outcome, the
   judge vote and the rule votes were stripped; `signals` (objective transcript facts) stayed.
2. **Blind labelling.** The 222 tasks were shuffled into 4 batches. Each batch went to two
   fresh Opus 5.5 subagents (A and B) with the v2 decision rules from `labels.py` as the only
   instruction and no access to the other labeler, the judge, or the old gold.
3. **Reconcile.** Per task the votes were {old gold, A, B} (audit) or {A, B} (new). Unanimous
   tasks were accepted. The 36 disagreements were ruled by the owner's delegate from the
   exported evidence and the rules (no other input).
4. **Pass 2.** A fresh Opus 5.5 reviewer saw the 36 rulings blind to the votes and was asked to
   refute each. It contested 8. Each was resolved at ground truth: 7 accepted (one after reading
   the full next message, which showed the restart step of a command failing), 1 rejected (a
   synthetic read-only demo under a test route is not the requested deployment; stays partial).
5. **Import.** `labels import-gold --by user` in three files, superseding every audited row
   (holdout rows keep `tag=holdout-2026-10-08`). Reasons name the method: `xval 2026-10-08:
   3/3 agree` / `2/2 agree` / `owner ruling (xval 2026-10-08): …`. Backup:
   `gold.jsonl.pre-xval-20261008.bak`. Transcript-bearing export files were deleted after import.

## Corrections to the old gold (15 of 182)

| direction | n | what the rules said |
|---|---|---|
| fail → unknown | 2 | cut mid-work with no result (rule 3), not a stall |
| fail → partial | 3 | part landed, or blocked with a correct diagnosis the user then acted on |
| unknown → fail | 2 | turn ended on a connection error (rule 5); a promise with no result and no interrupt is a stall |
| success → unknown | 3 | session ended on a handoff or the reply is not shown (rule 6) |
| success → partial | 2 | user pushed back on part of the answer; the deploy delivered was a stub |
| unknown → success | 1 | work committed, user pre-approved and moved on (rule 1) |
| partial → success | 1 | the artifact asked for was staged; user moved on (rule 1) |
| unknown → partial | 1 | edits made, tests failed after the last edit, nothing reported done |

Net: the old gold was success-heavy at the margins (6 of 15 corrections moved a success down)
and over-called fail on interrupted turns (5 of 15 moved a fail up). Both are the rule 3 / rule 6
boundaries, which are also where A and B disagreed most.

## Cross-family check (same day, later)

The 36 disagreement tasks were re-labelled blind by a GPT-family model (Codex CLI 0.157.1,
default model, OpenAI subscription; same packet and rules; the owner rulings and all Claude votes
hidden). It agreed with the owner ruling on **16/36**. The 20 splits sort into two kinds:

- **Rubric deviation (17).** GPT labels `partial` whenever any work remains in the session
  ("other implementers still working", "slide edits deferred pending the user's go", "further
  authorized work still running") and `unknown` whenever the final message is in progress, which
  overrides rule 1 (the user's next message approving or moving on → success) and rule 6. Each was
  checked against the rules and rejected; none cited evidence the owner ruling had missed.
- **Accepted at ground truth (3).** A turn that ended on a promise with no interrupt was
  `fail` after pass 2; GPT read it as still underway, and rule 3 only gives `fail` for a *clear*
  stall → `unknown`. An empty final message at session end was `fail`; it can be a tool
  hand-back the export does not show → `unknown`. Edits followed by failing tests and no
  completion report was `partial`; nothing landed working → `fail` (rule 5).

The three rows were superseded in place (`by=user`, holdout tag kept). Net effect on the
instrument: none visible (judge 0.87 on stored votes, held-out 0.92 (54/59), precision 0.90
unchanged); final gold distribution success 142, partial 27, fail 18, unknown 35.

Read: the cross-family reviewer found no shared-blind-spot error in the rulings, but it also
showed that the v2 rules are not self-evident to a model that has not internalised them. A label
from another family is only comparable after the rules are applied as written.

## Limits

- Vendor independence: A, B, the pass-2 reviewer and the old gold are all Claude (Opus 5.5);
  the rulings are Fable 5.1. The GPT check above covers only the 36 disagreements, not the 186
  unanimous tasks.
- The export clips the request to 1,500 and the final message to 2,000 characters; 3 of the 36
  disagreements were ruled `unknown` because the answer, if any, fell outside the clip.
- Reasons in `gold.jsonl` are the labelers' and the delegate's own words (no transcript text),
  capped at 120 characters.
